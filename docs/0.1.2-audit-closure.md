# Reach 0.1.2 audit closure

Version 0.1.2 closes the findings in the audited 0.1.1 review without adding a
network capability or changing the diagnostic policy. The authoritative
contract remains `network-diagnostic-cli-design.md` version 0.1.0.

## Scope invariants

The release does not change probe selection, probe order, traffic triggers,
budgets, retries, concurrency, state-machine conclusions, aggregation, exit
meanings, privilege requirements, or capability boundaries. Complete typed
evidence remains available to Core. The default CLI view is only a projection
of the completed result.

## Finding closure

| Finding | 0.1.2 closure | Enforced by |
|---|---|---|
| Conflicting default-output contracts | The 0.1.1 note is marked historical. The root design is the sole current contract. Default completed output contains the verdict, check, all targets, meaning, actions when needed, and only Core-selected Key Evidence. | Completed-output contract tests |
| `System DNS` conflated OS name resolution with direct DNS | Ordinary summaries say `Name resolution`; longer semantic text says `System name resolution`. Direct DNS remains failure-only diagnosis. | Terminology invariant test |
| Windows IP Helper status occupied ICMP wire fields | Native IP Helper status is represented by `IcmpNativeStatus::WindowsIpHelper`; `raw_type` and `raw_code` remain absent unless a wire ICMP header supplied them. | Platform model and presentation tests |
| Snapshot wording claimed an unobserved time change | The output describes a captured-fact cross-reference inconsistency and makes no temporal-stability assertion. | Snapshot assertion test |
| Deadline tail looked like a larger timeout budget | A timeout says that no result arrived before the fixed deadline. Scheduler/completion tail remains internal and is not shown as part of the budget. | Deadline wording test |
| Neighbor absence and missing observations were conflated | `NotSampled`, observed `Absent`, `Unknown`, and `Unavailable` are distinct typed states and render distinctly. | Platform and presentation semantic tests |
| Initial/current path labels implied a time transition | Evidence is source-oriented: `Snapshot path inference` and `Targeted OS path query`. | Completed-output evidence tests |
| Zero duration invited a false sub-millisecond claim | Equal clock readings are described as `the same observable clock reading`. | Duration semantic test |
| Raw OS identifiers leaked into default output | Raw enum values, GUIDs, native statuses, full capability inventories, and non-key attempts are retained internally but omitted from the default projection. | Context non-leak and native-status tests |
| Singular/plural wording was wrong | Target-dependent wording uses singular or plural forms from the actual address count. | Singular/plural tests |
| Narrow layouts were not adaptive | Below 60 columns target records are vertical; 60–79 columns use a compact table; 80 columns and above use the normal table. Prose, headings, fields, errors, and evidence wrap to the detected width. | Unicode display-width tests at 20, 40, 59, 60, 80, 120, 140, and 300 columns |
| Release tag and artifact source differed | All source and documentation changes precede the release-gate commit. The tag, release-gate CI head, and artifact-producing source must be the same commit. Run-specific evidence is attached to the GitHub Release instead of committed afterward. | Release procedure and attached evidence |

## Default-output invariants

- CLI does not choose evidence; it renders `CompletedDiagnostic::key_evidence`.
- Context-only Attempts cannot appear in default output.
- A retry selected as evidence is numbered so repeated observations remain
  distinguishable.
- ICMP success is not presented as proof that a TCP or application service
  works. TCP success is not presented as proof of an application protocol.
- Timeout, refusal, silence, absence, unknown, and unavailable remain distinct.
- Clean success omits diagnostic expansion and Key Evidence.
- Full Attempt and supporting facts remain in the completed internal result.

## Release evidence

The GitHub Release carries a run-specific evidence file beside the six native
archives. It records the exact source SHA, tag target, workflow run, test and
build results, runner image information, actual stable `rustc` and `cargo`
versions, `Cargo.lock` SHA-256, archive SHA-256 values, archive contents, and
executable mode checks. No Rust compiler version is pinned.
