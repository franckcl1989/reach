# Reach 0.1.0 implementation traceability

The sole product-scope authority is `network-diagnostic-cli-design.md`. This
file is an engineering index, not a substitute for that document. “Implemented”
means the product behavior and automated contract tests exist. It does not
replace the native release evidence required by design sections 23.4, 30.3,
31.7, and Definition-of-Done items 1, 26, and 27.

| Scope | Design sections | Implementation | Evidence / release gate |
|---|---:|---|---|
| Product and CLI input contract | 1–6 | Implemented | Core exclusively parses strict port, IP, scoped IPv6, IDN, and hostname syntax before snapshot capture. CLI exposes only `reach <address> [port]` plus conventional help/version. |
| Initial passive snapshot | 7 | Implemented | Interface, route, routing-policy, and resolver facts carry provenance and a continuous-clock capture window. Typed path/resolver inconsistencies are retained and only affect their related analysis. |
| Current path and Neighbor facts | 8, 10 | Implemented | Windows uses traffic-free `GetBestRoute2`; Linux/macOS explicitly report that the exact future-operation path cannot be proven without contaminating the boundary. Exact Linux/Windows Neighbor readers, shared pre-state coordination, and bounded convergence are implemented when an identity is known. |
| System resolver and formal targets | 9 | Implemented | Exactly one normal OS resolver call, no product timeout, raw order/duplicates retained, stable formal-target dedup, cancellation does not wait for an uninterruptible worker. |
| TCP primary check | 11 | Implemented | One or two explicit Attempts, retry only after Timeout, actual endpoints retained, explicit results terminal, socket/path comparison retained. |
| ICMP and failure diagnosis | 12–16 | Implemented | Ordinary-user Windows IP Helper / Unix datagram ICMP, fixed target/next-hop budgets, Neighbor gates, on-link stop, and non-overwriting explanatory diagnosis. |
| Resolver-failure DNS diagnosis | 17–18 | Implemented | Typed resolver-source applicability, applicable-candidate analysis, A/AAAA parallelism, exact UDP/TCP retry and transition rules, diagnostic-only boundary, dependency facts, and no recursive target diagnosis. |
| Results, evidence, aggregation | 19–20 | Implemented | Typed primary outcomes, conclusions, diagnostic conclusions, deterministic evidence IDs, key-evidence roles, mixed/zero-target aggregation, and fixed exits. |
| Output, exit, cancellation | 21–22 | Implemented | Completed results only on stdout; errors/cancellation/progress only on stderr; TTY-only progress; terminal-safe escaping; fixed 0/1/2/130. |
| Capability and permission contract | 23 | Implemented | Capability states are explicit and native tests exercise every 23.4 category. Windows x86-64 is locally verified; the other five native matrix jobs remain a release gate. |
| Time, concurrency, resource bounds | 24 | Implemented | Continuous/boottime platform clocks, fixed local deadlines and retry limits, four-wide lazy schedulers, finite hops, no recursive dependency expansion, and resource-exhaustion terminal handling. |
| Dependency policy | 25 | Implemented | ADR 0002 records the mature-crate-first audit and each unavoidable platform/API boundary. `Cargo.lock` fixes the audited dependency graph. |
| Core abstractions and state machines | 26–27 | Implemented | The Core is platform-independent, synthetic-testable, and owns all product decisions; platform and CLI layers do not decide diagnoses. |
| Fixed parameters and conclusion boundaries | 28–30 | Implemented | Versioned policy constants and tests lock every budget, limit, aggregate rule, and conservative conclusion boundary. |
| Automated acceptance suites | 31 | Implemented locally | Unit, property/fault, native Windows integration, CLI process, strict lint, stable-toolchain, Windows x86-64 build, and Linux x86-64 cross-check pass. The other four builds and all five non-local native executions remain CI release gates. |
| Work packages and Definition of Done | 32–34 | Native release gate pending | WP1–WP7 are implemented. WP8 and DoD 1/26/27 require a successful run of all six native CI jobs and their artifacts. |

## Current evidence

- `cargo fmt --all --check`
- `cargo clippy --workspace --all-targets --locked -- -D warnings`
- `cargo test --workspace --all-targets --locked`
- `cargo audit` (no vulnerabilities; the documented transitive `paste` maintenance warning remains)
- `cargo machete --with-metadata` (no unused direct dependencies)
- native Windows x86-64 workspace build and Linux x86-64 workspace cross-check
- Native ordinary-user Windows x86-64 TCP, ICMP, route, current-path,
  Neighbor, direct-DNS, cancellation, clock, CLI, and snapshot tests
- `cargo build --release --locked -p reach-cli` and native executable smoke tests

The exact platform status and test names are recorded in
`docs/0.1.0-native-capability-matrix.md`.

## Remaining release gate

Run `.github/workflows/ci.yml` in a GitHub repository. All six native matrix
jobs must pass and publish their one-executable archives. Cross-compilation is
intentionally not counted as capability proof.
