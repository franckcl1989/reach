# Reach 0.1.3 baseline closure and release contract

Version 0.1.3 closes distribution, resolver-evidence, and release-governance
gaps without adding a diagnostic network feature. The authoritative product
behavior remains `network-diagnostic-cli-design.md` version 0.1.0 as amended by
its explicit single-executable and static-Linux clauses.

## Scope invariants

The TCP, ICMP, Neighbor, path, and failure-only Direct DNS state machines keep
their existing triggers, budgets, retries, concurrency, terminal priority, and
exit meanings. No UDP port check, application protocol, scan, discovery,
capture, repair, elevation, external diagnostic command, or new CLI mode is
added.

## Release artifacts

| Artifact | Release target | Runtime dependency contract |
|---|---|---|
| `reach-linux-x86_64.tar` | `x86_64-unknown-linux-musl` | Fully static ELF: no interpreter, needed library, runtime search path, or GLIBC symbol version |
| `reach-linux-aarch64.tar` | `aarch64-unknown-linux-musl` | Same |
| `reach-macos-x86_64.tar` | `x86_64-apple-darwin` | One Mach-O using only `/System/Library` and `/usr/lib` |
| `reach-macos-aarch64.tar` | `aarch64-apple-darwin` | Same |
| `reach-windows-x86_64.tar` | `x86_64-pc-windows-msvc` with `+crt-static` | Windows system DLL allowlist; no VC/UCRT app runtime or third-party DLL |
| `reach-windows-aarch64.tar` | `aarch64-pc-windows-msvc` with `+crt-static` | Same |

Every archive contains exactly one executable. Release automation inspects the
build output, packages it, extracts it, verifies executable hash identity,
inspects the extracted executable again, and runs version, invalid-input,
IPv4-loopback TCP, and `localhost` TCP smoke tests against the extracted file.

## Supported environment floor

The floor is intentionally limited to environments exercised by the 0.1.3
release workflow. A lower version is unsupported rather than “probably works.”

| Platform / architecture | Supported floor | Release evidence |
|---|---|---|
| Linux x86-64 | Linux kernel 6.8; static executable also starts in Rocky Linux 8 and 9 user spaces | Native Ubuntu 22.04 VM plus container user-space smoke |
| Linux ARM64 | Linux kernel 6.8; static executable also starts in Rocky Linux 8 and 9 user spaces | Native Ubuntu 22.04 ARM64 VM plus container user-space smoke |
| Windows x86-64 client | Windows 11 | Actual archive under Windows 11 ARM x64 emulation |
| Windows x86-64 server | Windows Server 2022 | Native runner |
| Windows ARM64 client | Windows 11 | Native runner |
| Windows ARM64 server | Unsupported | No release claim |
| macOS x86-64 | macOS 15 | Native Intel runner |
| macOS ARM64 | macOS 14 | Native Apple Silicon runner |

Runner image versions, exact OS/kernel versions, and compatibility container
digests are recorded in the release evidence asset. The Linux 6.8 gate fails if
the selected floor runner no longer provides that kernel line.

## Linux system name resolution

A static musl `getaddrinfo` is not treated as the host glibc NSS resolver.
Before primary name-resolution network traffic, Reach parses the host
`/etc/nsswitch.conf`; it executes reached `files` and `dns` sources in policy
order using `gai-core`, `/etc/hosts`, and `hickory-resolver` configured from
`/etc/resolv.conf`. Search/domain, ndots, A/AAAA, configured resolver order,
raw order, and duplicate facts are retained at the selected library boundary.

A malformed policy, reached unsupported NSS source, or reached resolver option
that cannot be represented faithfully is a required-capability execution error
(exit 2). A later unsupported source is harmless only when a supported earlier
source has already terminated the NSS chain. This formal DNS source remains
separate from failure-only Direct DNS diagnosis.

## Evidence and presentation corrections

- A successful system resolver result that formed formal targets is Context,
  not PrimaryDecision.
- A platform negative/no-address result means no usable IPv4 or IPv6 address;
  it is not promoted to a claim that the hostname globally does not exist.
- Direct DNS NXDOMAIN remains scoped to that protocol response and cannot
  rewrite system-resolver history.
- Attempt numbers are local to one logical operation. Two TCP retries followed
  by one ICMP check render as `TCP connect #1`, `TCP connect #2`, and
  `ICMP Echo`; internal `AttemptId` remains unchanged.

## CI and release identity

`ci.yml` owns pull-request/master quality and six native release-configuration
conformance jobs. `release.yml` owns tag/version/source verification, exact
target conformance, artifact inspection, compatibility tests, packaging, and
publication. `cargo audit` 0.22.2 and `cargo machete` 0.9.2 are exact tool
versions in both gates.

The project owner explicitly requires an unpinned current stable Rust
toolchain. Therefore 0.1.3 does not add `rust-toolchain.toml` or `rust-version`.
Each target provenance instead records actual `rustc`/`cargo`, source SHA,
`Cargo.lock` and Cargo-config hashes, target, profile, features, target flags,
link configuration, runner image, and build-affecting Rust flags. Any compiler
or dependency change requires all gates again.

Tag publication is all-target gated. The workflow creates a draft only after
all target jobs pass, verifies all six archives plus evidence/checksum assets,
then makes it public. Existing releases or asset replacement are rejected.

## Distribution trust exception

No Authenticode certificate, Apple Developer ID/notarization identity, or
Linux detached-signature key is configured. Version 0.1.3 is therefore an
unsigned public release; users may see OS trust warnings. SHA-256 checksums and
source/configuration provenance are provided, but they are not a substitute
for platform code signing. Signing becomes a separate release blocker if the
project later adopts a signed-distribution policy.
